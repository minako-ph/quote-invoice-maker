## 指摘（F-1〜F-7。この順に適用）

### F-1【最重要・課金E2Eブロッカー】backendにCORSがなく、thanks/license-recoverのfetchがブラウザで失敗する

- 対象: `backend/src/routes/index.ts`（または app.ts）、`backend/test/licenseRoutes.test.ts`
- 事象: `web/thanks.html`・`web/license-recover.html` はGitHub Pages（別オリジン）からCloud Runへ `fetch POST（content-type: application/json）` する。プリフライト（OPTIONS）と `Access-Control-Allow-Origin` の応答がないため、ブラウザ上で必ず失敗する。受入基準§9-6（課金E2E）のブロッカー。
- 修正: `hono/cors` を **`/license/claim` と `/license/recover` のみ**に適用する（`app.use('/license/claim', cors()); app.use('/license/recover', cors());` 相当。origin は `'*'`・credentialsなしでよい——認可の実体は sessionId／email＋IPクールダウンであり、CORSは境界ではない）。`/license/verify` はGASサーバ間通信のため不要。`/stripe/webhook` には付けない。未設定時503の配線（routes/index.tsの early return 側）にも同様にCORSが効くよう、use登録は分岐の前に置くこと。
- テスト: licenseRoutes.test に (a) `OPTIONS /license/claim` がプリフライト成功（204/200＋`Access-Control-Allow-Origin`） (b) `POST /license/claim` 応答に `Access-Control-Allow-Origin` が付く、を追加。
- 記録: decisions.md に1行（「CORSはclaim/recoverのみ・origin '*'・理由」）。

### F-2【V-1の実効性】スパイクが本番条件（非表示の_帳票シート）を検証していない

- 対象: `apps-script/src/server/spike.ts`、`apps-script/src/server/pdf.ts`／`sidebarApi.ts`、`docs/setup/spike-v1-v2.md`
- 事象: `probeExportPdf()` は**可視のアクティブシート**の A1:C5 を出力するが、本番は **`hideSheet()` 済みの `_帳票`** のgidを出力する。非表示シートのgid exportは挙動が異なり得るため、現状のスパイクが成立しても本番が失敗する余地が残る（V-1は本番同条件で検証しなければ意味が薄い）。
- 修正（2点セット）:
  1. **本番側を構造的に安全化**: export実行部を共通ヘルパ（例 `exportRenderedPdf(rendered, fileName)`）に切り出し、「`_帳票` を `showSheet()` → `SpreadsheetApp.flush()` → export fetch → `finally` で `hideSheet()`」とする。同一方式内の堅牢化でありCR-3の方式・スコープ変更ではない（一瞬タブが見える副作用は許容。decisions.mdに1行）。
  2. **probeを本番フロー同型に**: `probeExportPdf()` はコード内固定のダミー書類（サンプル明細相当）＋固定プロファイルで `calcDocument`→`renderTemplate`→上記共通ヘルパを呼ぶ形にする。これでV-1の検証対象は「4スコープトークンのexport URL認可」に純化され、A4レイアウトも同時に目視できる。
- あわせて `docs/setup/spike-v1-v2.md` の手順（「A1:C5に値を入れる」）を新フローに合わせて更新。

### F-3【実バグ】folderAliveがゴミ箱入りフォルダを「生存」と誤判定する

- 対象: `apps-script/src/server/drive.ts`
- 事象: Drive API v3 の `Files.get` は既定fieldsに `trashed` を含まない。`file.trashed !== true` は常に真（undefined）となり、ユーザーが「帳票」フォルダをゴミ箱に入れても生存扱い→**以後のPDFがゴミ箱内フォルダへ保存され続け、ユーザーから消えたように見える**。
- 修正: `Drive.Files.get(folderId, { fields: 'id, mimeType, trashed' })` とfieldsを明示する。`spike.ts` の取得確認も同様にfields明示に揃えると丁寧（必須ではない）。
- 確認: V-2スパイク実行時に「フォルダをゴミ箱へ→再export→新フォルダが再作成される」を目視項目に追加（spike-v1-v2.mdへ1行）。

### F-4【無言劣化ガード】fetchPdfBlobが「200だが非PDF」を検知しない

- 対象: `apps-script/src/server/pdf.ts`
- 事象: HTTP 200でHTML等が返るエッジで、HTMLを `.pdf` として保存する無言の劣化が起こり得る（probeには%PDF検査があるのに本番にない）。
- 修正: probeと同じ `%PDF` マジックバイト検査を `fetchPdfBlob` に追加し、非PDFは『PDFの生成結果が不正です（…）』の原因つきエラーにする（N-4）。

### F-5【記載要件ガード】プロファイル未設定・登録番号なしでも適格様式が黙って出力される

- 対象: `apps-script/src/server/sidebarApi.ts`（exportActiveToPdf）、`profile.ts`（validateProfile）、`sidebar.html`（ラベル・エラーガイド）
- 事象: (a) 発行者氏名が空でもPDF出力でき、記載事項①（発行者氏名/名称）欠落の書類が生成される。(b) `taxable=true` かつ登録番号空だと「登録番号のない適格様式風」の帳票になる（§6-3①を満たさず、区分記載様式でもない）。
- 修正:
  1. `exportActiveToPdf` の冒頭で `profile.name === ''` はエラー『発行者プロファイル（氏名/名称）を設定してください（サイドバー「発行者プロファイル」から）』。あわせて `taxable && registrationNumber === ''` もエラー（下記メッセージ）。
  2. `validateProfile` を強化: `taxable=true` は登録番号必須。エラーメッセージは『適格請求書発行事業者の場合は登録番号（T＋13桁）が必要です。未登録・免税事業者の方はチェックを外してください（区分記載請求書の様式で出力します）』。
  3. `sidebar.html` のチェックボックスラベルを『適格請求書発行事業者（登録番号あり）』へ変更。
- 理由: FR-5/6の記載要件を運用でなく構造で守る（「根拠のない値は返さない」の帳票版）。ユーザーはまだゼロのため後方互換の考慮は不要。
- テスト: profile.test に「taxable=trueで登録番号空→ng」を追加。golden・既存テストの期待値は変えない。

### F-6【推奨・公開後の再デプロイ回避】レビュー依頼（marketing §8）の骨組みを今入れておく

- 対象: `apps-script/src/sidebar/sidebar.html`、`apps-script/src/server/`（フラグ保存の小関数）
- 事象: 「初回のPDF保存成功直後に1回だけレビュー依頼」（marketing §8）が未実装。公開後にGASを変更すると版デプロイ・再審査の手戻りになるため、プレースホルダで今実装しておく。
- 修正: `REVIEW_URL = ''` プレースホルダを追加し、初回export成功時に1回だけ、status領域に控えめなリンク（『役に立ったらストアでレビューをお願いします』程度）を表示。表示済みフラグはUserProperties（例 `reviewPromptShown`）。**URL空の間は何も表示しない**。再表示・報酬付き文言は書かない（marketing §8）。
- 記録: 公開後のURL差替は人間タスク（Notion側に追記済み）。

### F-7【軽微】明細の税率セル空欄が黙って10%既定になる

- 対象: `apps-script/src/server/sheets.ts`（readDocument）
- 事象: プルダウン外のコピペ等で税率セルが空のとき、黙って10%として計算される（根拠のない既定）。
- 修正: 品目・数量・単価のいずれかが入っている行で税率が解釈不能なら、エラー『明細N行目の税率を選択してください（10% / 8%（軽減）/ 対象外）』を投げる。
