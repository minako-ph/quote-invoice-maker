## 1. 背景・目的・成功基準

フリーランス・零細事業者向けのGoogle Sheets用エディタアドオン。スプレッドシート上で (1) 見積書→請求書のワンクリック変換 (2) 源泉所得税の自動計算 (3) 適格請求書の記載要件を満たす消費税計算（端数処理設定つき） (4) 電子帳簿保存法の実務に沿ったファイル名でのPDF出力とDrive自動保存、を一気通貫で提供する。「請求書を作る→正しく計算する→正しい名前で保存する」の毎月の反復ペインを、シートから出ずに解決する。

**成功基準（ビジネスKPI、§11）**: 最初の10インストールで有料転換1件以上／12ヶ月でMRR¥20,000以上。収益推計（レポートv2.0: 初月¥5,000〜2万・6ヶ月¥3〜10万・定常¥10〜30万）は参考値であり保証ではない。

## 2. スコープ／非スコープ／前提

**スコープ**: Google Sheets用エディタアドオン（サイドバーUI）＋ライセンス専用バックエンド（Stripe連携）＋公開に必要なLP・プライバシーポリシー・利用規約・特定商取引法表記。

**非スコープ**: インボイス登録番号の照会・真正性検証（CR-1）／経理部門向け機能＝承認ワークフロー・複数人運用・会計仕訳連携（CR-2）／メール自動送付（Gmailスコープが必要になるため恒久非対応。PDFの送付はユーザー自身が行う）／電子署名・タイムスタンプ／受発注管理・入金消込／Excel版／英語帳票（v1.1判断）／適格返還請求書・納品書・領収書テンプレート（v1.1判断）／税込単価入力モード（v1は税抜単価入力に統一。§6-2の端数処理を単純・検証可能に保つため）。

## 3. 利用者

一次: 国内のフリーランス・個人事業主（デザイナー・ライター・エンジニア等、月1〜10通の見積書・請求書を自分で発行する層）。二次: 零細法人（社長が自ら発行する規模）。
**対象外を明示**: 経理部門・複数人での運用・税理士事務所での代理発行（CR-2）。

## 4. 機能要件（FR）

- **FR-1 書類の新規作成**: サイドバーから「見積書」「請求書」を選ぶと、所定様式の入力シートを生成する。項目: 書類種別・書類番号（プレフィックス＋連番の自動採番、手動上書き可）・発行日・取引年月日（または期間）・宛名（取引先名）・件名・明細（品目／数量／単価（税抜）／税率 10%・8%・対象外／源泉対象フラグ）・備考。請求書はさらに支払期限・振込先、見積書は有効期限を持つ。
- **FR-2 見積→請求変換**: 見積書の入力シートからワンクリックで請求書の入力シートを生成する（明細・取引先を引継ぎ、書類番号・発行日を更新、支払期限・源泉税欄を有効化）。逆方向（請求→見積）は対象外。
- **FR-3 消費税計算**: 明細から税率区分ごとの小計・消費税額・合計を自動計算する。消費税額は税率ごとに区分した合計額に税率を乗じ、**1書類につき税率ごとに1回だけ**端数処理する（割戻し計算に固定。明細行ごとの端数処理→合算は行わない。§6-2）。端数処理方式は設定（既定=切捨て）。
- **FR-4 源泉所得税計算**: 書類単位のトグン（既定は発行者プロファイルの設定値）。源泉対象行の合計額を対象に、§6-1の式（10.21%、100万円超部分20.42%、1円未満切捨て）で算出し、「差引請求額 = 税込合計 − 源泉徴収税額」を帳票に明示する。対象額は既定=税抜（消費税を区分記載する本テンプレでは許容される取扱い）、設定で税込（原則）に切替可。**源泉徴収の要否・対象該当性の判断は利用者に委ねる**旨をUI・ヘルプに明記する（源泉徴収は支払者側の義務であり、請求書への記載は実務慣行としての参考計算である）。
- **FR-5 適格請求書テンプレート**: §6-3の記載事項6項目を必須項目とするA4縦1種。見積書・請求書は同一レイアウトで表題・文言を切替。発行者情報（氏名/名称・登録番号・住所・振込先）はプロファイル（FR-11）から差し込む。
- **FR-6 免税事業者モード**: プロファイルで「適格請求書発行事業者ではない」を選ぶと、登録番号欄と適格請求書であることを示す文言を出力しない様式（§6-4の区分記載請求書の記載事項を満たす）に切り替わる。計算エンジンは共通。
- **FR-7 PDF出力**: 帳票シートをA4縦のPDFとして生成する（実現方式はV-1の検証結果に従う。方式変更でスコープを増やさない＝CR-3優先）。
- **FR-8 電帳法対応のファイル命名・Drive保存**: 生成PDFを既定命名 **「YYYYMMDD_取引先名_税込金額.pdf」**（日付=発行日・金額=税込で統一。§6-5の国税庁例示に準拠）で、アドオンが作成した保存フォルダ（既定名「帳票」、配下に「請求書」「見積書」サブフォルダ）へ保存する。同名衝突時は末尾連番を付す。命名要素は取引先名の記号等を機械的に整形してよいが、日付・取引先・金額の3要素と順序は固定。
- **FR-9 無料枠と使用量表示**: 無料枠は**月3枚**（PDF出力の成功1回＝1枚。再出力も計上する）。カウントはGoogleアカウント単位（UserPropertiesベース）で行い、当月使用量と残数をサイドバーに常時表示する。プロパティ消去による無料枠リセットの悪用は許容する（柱3 R3-1と同等の割り切り。対策コードを書かない）。
- **FR-10 ライセンス**: 有料化はライセンスキー方式（柱3 R3-2フローと同型）。サイドバーからStripe Checkoutへ誘導→購入完了ページでキーを表示（コピー導線つき）→キー入力で解錠。キーはGoogleアカウントに紐づけて保存し、再表示手段（メールアドレス照合）を提供する。解約はStripeカスタマーポータル。解約後も当該課金期間の満了までPro機能を利用できる（特商法表記と一致させる）。
- **FR-11 発行者プロファイル**: 氏名/名称・住所・登録番号（**T+13桁の形式チェックのみ。チェックデジット・真正性の検証はしない**＝CR-1）・課税/免税区分・端数処理方式・源泉税の既定ON/OFF・源泉対象額の税抜/税込・振込先・書類番号プレフィックスを、Googleアカウント単位で保存する。
- **FR-12 出力台帳**: PDF保存成功時に台帳シートへ1行追記する（発行日・書類種別・書類番号・取引先・税込金額・ファイルへのリンク）。日付・金額・取引先を持つため電帳法の索引簿的にも活用できるが、**法的要件の充足を保証する表現はしない**（CR-4）。
- **FR-13 サンプル書類生成**: ワンクリックでサンプル明細入りの見積書を生成できる（オンボーディング用。受入基準5の前提）。
- **FR-14 ヘルプ・正直表記・クロスセル**: サイドバー内ヘルプに、使い方／できないこと（§CR-4の正直明記3点）／「本アドオンは税務助言を行わない」旨／源泉徴収の位置づけ（FR-4注記）を常設する。取引先リストの一括検証ニーズには「会社リストクリーナー」への導線を張る（CR-1の受け皿）。

## 5. 絶対制約（CR）— 違反はプロダクト戦略・審査・信頼を毀損する最優先制約

- **CR-1 インボイス登録番号の検証機能を搭載しない**: 照会・真正性確認の機能もコードも作らない（形式チェックのみ可）。理由: (a) 柱3のコア価値との自社共食い回避 (b) 承認待ちのインボイスWeb-APIに依存する機能を作らない規律の踏襲。スコープ拡大のPR・提案も作らない。
- **CR-2 フリーランス・零細限定**: 承認ワークフロー・複数人運用・仕訳連携等の経理部門向け機能に踏み込まない（LayerX利益相反の回避）。マーケ文言も「経理部門向け」を名乗らない。
- **CR-3 OAuthスコープは以下の4点に固定**: `spreadsheets.currentonly`／`script.external_request`／`script.container.ui`／`drive.file`。restrictedスコープ（Drive全体・Gmail等）は恒久不使用（CASA監査の構造的回避）。スコープ差分はCIでガードする。V-1/V-2の結果が不成立でも安易にスコープを増やさず、方式変更で吸収する（増設は本書の改訂＝明示的な事業判断を要する）。
- **CR-4 誇大コピー禁止・正直な記載**: 「2026年義務化」等の誤表現を使わない（電子取引データ保存の義務化は2024年1月に開始済み）。検索要件には緩和（基準期間売上高5,000万円以下＋ダウンロード応需等）があることを正直に明記する。「唯一」「完全」「税務署公認」を使わない。正直明記3点=①登録番号の真正性は検証しない ②税務助言ではない（源泉徴収の要否等の判断は利用者・税理士） ③電帳法の法的要件充足を保証しない（命名・台帳は実務に沿った一手段）。
- **CR-5 シークレット運用**: ローカルは.env（gitignore）、GASはScript Properties、バックエンドはSecret Manager等のプラットフォーム機構。リポジトリ・コード・ログにキーを置かない。

## 6. 税務・法令仕様（確定値。receiving基準・goldenテストの根拠）

### 6-1 源泉所得税（報酬・料金）
- 税率: 支払金額100万円以下は**10.21%**、同一人への1回の支払が100万円を超える部分は**20.42%**（いずれも復興特別所得税を含む）。式: A≦100万円 → A×10.21%／A＞100万円 → (A−100万円)×20.42%＋102,100円。
- 端数: 求めた税額に1円未満の端数があるときは**切り捨てる**（端数処理は合算後に1回）。
- 対象額: 報酬・料金等に消費税等が含まれる場合、原則は税込全額が対象。ただし**請求書等で消費税等の額が明確に区分されている場合は税抜（報酬・料金の額のみ）を対象として差し支えない**。インボイス制度開始後も同取扱い。→ 既定=税抜、設定で税込。
- 出典: 国税庁タックスアンサー No.2795（原稿料や講演料等）・No.2792関係Q&A（1円未満切捨ての計算例）。https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2795.htm

### 6-2 消費税の端数処理（適格請求書）
- 「税率ごとに区分した消費税額等」の1円未満端数は、**一の適格請求書につき税率ごとに1回**の端数処理を行う（消令70の10、基通1-8-15）。方式（切上げ・切捨て・四捨五入）は事業者の任意 → 設定項目（既定=切捨て）。
- 個々の明細行ごとに端数処理した額を合算して記載することは認められない（割戻し計算の場合）。本アドオンは**割戻し計算に固定**（税抜区分合計×税率→1回処理）。
- 税抜・税込は書類内でいずれかに統一が必要 → v1は税抜単価入力に統一。
- 出典: 国税庁インボイスQ&A 問57・パンフレット「インボイス制度の理解のために」。https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf

### 6-3 適格請求書の記載事項（テンプレ必須項目）
①発行者の氏名または名称**及び登録番号** ②取引年月日 ③取引内容（軽減税率対象品目である旨） ④税率ごとに区分して合計した対価の額（税抜または税込）**及び適用税率** ⑤税率ごとに区分した消費税額等 ⑥交付を受ける者の氏名または名称。

### 6-4 区分記載請求書（免税事業者モード）
①発行者の氏名または名称 ②取引年月日 ③取引内容（軽減税率対象品目である旨） ④税率ごとに区分して合計した**税込**対価の額 ⑤交付を受ける者の氏名または名称。登録番号は記載しない。適格請求書と誤認させる記載（登録番号様の番号等）をしない。

### 6-5 電子帳簿保存法（電子取引・発行控えの保存）
- 電子取引データ保存の義務化は**2024年1月開始済み**（送った側=発行控えも保存対象）。
- 検索要件: ①取引年月日・取引金額・取引先で検索できる ②日付・金額の範囲指定 ③2項目以上の組合せ（②③はダウンロード応需で不要）。規則的ファイル名による充足例が国税庁一問一答に例示されている（例: 「20221031_㈱国税商事_110000」＝**日付_取引先_金額**）。
- 緩和: 判定期間に係る基準期間の売上高**5,000万円以下**＋ダウンロード応需、または出力書面を日付・取引先ごとに整理して提示できる＋ダウンロード応需の場合、検索機能の確保は不要（令和6年6月版一問一答）。→ CR-4によりこの緩和を掲載文・ヘルプで正直に明記。
- ファイル名の金額は税込/税抜いずれも可（統一が必要）→ 本アドオンは**税込で統一**。
- 出典: 国税庁 電子帳簿保存法一問一答【電子取引関係】（令和6年6月）。https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/0024005-113_r603.pdf

## 7. 非機能要件（N）

| # | 要件 |
|---|---|
| N-1 | **計算根拠の明示**: すべての自動計算値に根拠（適用税率・端数処理方式・源泉税率の内訳）を帳票の注記またはサイドバーで提示する。根拠のない値は返さない |
| N-2 | 応答性: 1書類のPDF生成〜保存を通常30秒以内目標・GASの6分制限内に完結。進捗表示を行い、無言で失敗しない |
| N-3 | **データ最小化**: シートの内容（明細・取引先等）を外部に送信しない。外部送信はライセンスキー検証（キー文字列のみ）とStripe決済ページへの遷移に限る。無料利用の範囲ではシート外へのデータ送信ゼロ |
| N-4 | 障害時挙動: ライセンス検証不能時はfail-closed（一時的にFree扱い）とし状態をサイドバーに表示。PDF生成・保存の失敗は原因を提示する |
| N-5 | 保守: 事業全体の週1時間枠内（本プロダクト単体は月2時間以内目標）。FAQ・アプリ内ヘルプで問い合わせを前倒しで削減 |
| N-6 | UIは日本語のみ（v1）。リスティングの英語併記はmarketing.mdで判断 |
| N-7 | **税制の年次点検**: 税率・様式・電帳法の改正を年1回点検する運用を保守手順に明記する（改正リスクの受け皿） |

## 9. 受入基準（公開条件）

1. FR-1〜14・CR-1〜5・N-1〜7を満たす（**CRはコードレビューの明示的検証項目**とする）。
2. §6-6のgoldenテストが全件一致（自動テスト緑。golden値の自動上書き禁止）。
3. OAuth検証（ブランド＋sensitive審査）通過。提出物のスコープがCR-3の4点のみであることを確認。
4. Marketplace掲載審査通過。LP・プライバシーポリシー・利用規約・特商法表記が公開済み。
5. E2E: 新規ユーザーが「インストール→サンプル生成→見積書PDF→請求書へ変換→PDF→Drive保存確認」を5分以内（サンプル利用時3分以内）に完了できる。
6. 課金E2E: Checkout→キー表示→解錠→Pro枠反映→解約→期間満了までPro維持、が通しで動作。
7. V-1・V-2の検証結果がdecisions.mdに記録され、採用方式が確定している。
