# V-1/V-2 スパイク実行手順（引継書§12-3。人間・テストシートで約10分）

未検証事項 V-1（export URL の4スコープ認可）・V-2（Advanced Drive Service の drive.file 実挙動）を
実機で確定する手順。**結果は必ず docs/decisions.md に1行ずつ記録する**（要件書§9-7 受入基準）。

前提: `docs/setup/clasp.md` の手順で clasp push とテストシートへのインストールが済んでいること
（スパイクはアドオンのスクリプトに同梱済み。`exportPdfProbe` / `driveProbe` がエントリポイント）。

## 手順

1. アドオンをインストールしたテスト用スプレッドシートを開く。
   ※ セルへの事前入力は不要。probe はコード内固定のダミー書類を使い、**本番と同じフロー**
   （calc → 非表示の`_帳票`へ差し込み → export中のみ再表示 → PDF取得）で検証する。
   ※ **スクリプトエディタからの `exportPdfProbe` 直接実行は不可**（standalone 実行では
   `SpreadsheetApp.getActiveSpreadsheet()` が null になり本番フローに入れない）。
   必ずテストシートの**アドオンメニュー**から実行する。
2. 拡張機能 → 見積書・請求書メーカー → **「(dev) V-1スパイク」** を実行。初回は権限承認ダイアログが出る
   （**承認を求められるスコープが4点のみであることもここで目視確認**＝CR-3）。
3. 結果がダイアログ（alert）に全文表示されるので確認する:
   - `export fetch: OK`・`%PDFマジックバイト: OK` → **V-1成立**。
     シート下部の「_帳票」を再表示（シートタブ一覧→再表示）すると、A4差し込み結果を目視できる。
   - `失敗: PDFの生成に失敗しました（HTTP 401/403）` 等 → **V-1不成立**。表示全文を控える。
4. 同様にメニューの **「(dev) V-2スパイク」** を実行し、ダイアログを確認する
   （V-2はスクリプトエディタの `driveProbe` 実行でも可＝シートコンテキスト不要。エディタ実行で成立済み）:
   - `フォルダ作成: OK`・`PDFアップロード: OK`・`取得確認: OK` → **V-2成立**。
     マイドライブに「_v2probe_帳票」フォルダと `_v2probe.pdf` ができていることを目視確認
     （確認後、フォルダごと削除してよい）。
   - 例外発生 → **V-2不成立**。エラーメッセージを控える。
5. （V-2成立時の追加確認・F-3）本番E2Eで一度PDFを保存したあと、Driveの「帳票」フォルダを
   ゴミ箱へ入れて再度PDF出力し、**新しい「帳票」フォルダが再作成される**ことを確認する。
6. `docs/decisions.md` に結果を記録する（例）:
   - `2026-07-XX V-1成立: 本番同型フロー（非表示_帳票をexport中のみ再表示）でexport URL+OAuthトークン=%PDF確認（4スコープ・テストシート実機）→ FR-7はexport URL方式で確定`
   - `2026-07-XX V-2成立: Drive v3 Advanced Service（drive.file）でフォルダ作成・PDF保存・取得OK・ゴミ箱後の再作成OK → FR-8はAdvanced Drive方式で確定`

## 不成立時の動き（引継書§6・CR-3）

- **V-1不成立** → フォールバック(1): drive.file でアプリが新規作成したスプレッドシートへ帳票を複製し、
  そのファイルの export URL を叩く方式を試す（スパイクの改修が必要。実装者に差し戻す）。
  それも不成立なら **(2) 停止して人間判断**（スコープ追加・別方式への切替は要件書CR-3の改訂＝事業判断）。
- **V-2不成立** → 同様に停止して報告。**スコープ追加で解決しない。黙って代替しない。**

## 成立後（実装者側の作業）

- V-1/V-2 とも成立していれば、本実装（pdf.ts / drive.ts）は既に同方式で接続済みのため追加作業なし。
  サンプル書類で「見積→請求→PDF→Drive保存」のE2Eを通し、A4レイアウト品質を確認して微調整する。
