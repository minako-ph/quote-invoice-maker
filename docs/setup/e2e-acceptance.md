# E2E受入チェックリスト（要件書§9-5／§9-6の実施手順）

V-1/V-2スパイク成立後（`docs/setup/spike-v1-v2.md`）に人間が実機で実施し、
結果（合格日・気づき）を `docs/decisions.md` に1行残す。

## A. 新規ユーザー動線E2E（要件書§9-5）

**合格条件: インストール→サンプル生成→見積書PDF→請求書へ変換→PDF→Drive保存確認 が5分以内
（サンプル利用時は3分以内）に完了できること。** ストップウォッチで計測する。

### 手順（初期状態: プロファイル未設定・帳票フォルダなし）

- [x] 1. テストシートにアドオンをインストールし、サイドバーを開く（初回承認のスコープが4点のみであることを目視）
- [x] 2. 発行者プロファイルを設定（氏名/名称・住所・登録番号 T1234567890123・振込先）
- [x] 3. 「サンプルで試す」→ サンプル見積書シートが生成される
- [x] 4. 「プレビュー / 再計算」→ 集計と根拠注記が書き込まれる
- [x] 5. 「PDF出力・Driveに保存」→ 成功メッセージ（ファイル名＋リンク）
- [x] 6. 「見積書 → 請求書に変換」→ 請求書シート生成 → 再度「PDF出力・Driveに保存」
- [x] 7. Driveの「帳票」フォルダ（見積書/請求書サブフォルダ）と台帳シートを確認
- [x] 計測タイム: 約1分00秒（2026-07-24実測。受入値3分以内をクリア）

### 確認観点

**帳票PDF（請求書）の記載事項6項目（要件書§6-3・適格様式）**:
- [x] ① 発行者の氏名/名称 と 登録番号（T＋13桁）
- [x] ② 取引年月日（または期間）
- [x] ③ 取引内容（軽減税率対象品目に「※」と脚注「※は軽減税率対象品目」）
- [x] ④ 税率ごとに区分した対価の額（10%対象/8%対象）と適用税率
- [x] ⑤ 税率ごとに区分した消費税額等（消費税(10%)/消費税(8%)）
- [x] ⑥ 交付を受ける者の氏名/名称（「〇〇 御中」）

**そのほか**:
- [x] 根拠注記（N-1）: 端数処理方式・「税率ごとに1回」・源泉税の式（10.21%/100万円超20.42%・1円未満切捨て）が帳票注記に出ている
- [x] 源泉行: 源泉徴収税額（マイナス表記）と差引請求額が表示され、サンプル値と一致する
- [x] ファイル名: `YYYYMMDD_サンプル株式会社_<税込金額>.pdf`（日付=発行日・金額=税込整数）。同名で再出力すると `_2` 連番になる
- [x] 台帳行: 発行日・書類種別・書類番号・取引先・税込金額・ファイルリンクの6列が2行（見積・請求）追記されている
- [x] 使用量表示が 2/3 枚に更新されている
- [x] （免税モード）プロファイルで課税チェックを外す→登録番号欄を空にする→PDFに登録番号が出ず、税率ごとの**税込**対価の額の様式（§6-4）になる

**F-3 ゴミ箱→再作成確認（spike-v1-v2.md §5と同項目）**:
- [x] Driveで「帳票」フォルダをゴミ箱へ入れる → 再度PDF出力 → **新しい「帳票」フォルダが再作成され**、ゴミ箱内へ保存され続けないこと

## B. 課金E2E（要件書§9-6・Stripeテストモード）

**合格条件: Checkout→キー表示→解錠→Pro枠反映→解約→期間満了までPro維持、が通しで動作。**
前提: backendがCloud Run（またはローカル）で稼働し、Stripeは**テストモード**で
Product/Price（¥1,480税込）・Payment Link・カスタマーポータル・webhookが設定済み（backend/README.md）。
web/thanks.html・license-recover.html の `BACKEND_URL` が差し替え済み。

- [ ] 1. サイドバー（または直接Payment Link）からCheckoutを開き、**テストカード 4242 4242 4242 4242**
      （有効期限=未来の任意・CVC=任意3桁・郵便番号=任意）で購入する
- [ ] 2. 成功URLで thanks.html に遷移し、`session_id` からライセンスキーが表示される（コピー導線が動く）
- [ ] 3. サイドバーにキーを入力→「キーを登録して解錠」→ 状態が「Pro有効（月1,000枚まで）」になる
- [ ] 4. 使用量表示の上限が 3 → **1,000** に切り替わる（Pro枠反映）
- [ ] 5. license-recover.html に購入時メールアドレスを入力→同等のキーが再表示される
      （60秒以内の連投は429になることも1回確認）
- [ ] 6. Stripeカスタマーポータルで解約（期間末解約）する
- [ ] 7. **期間満了までPro維持の確認（代替手順で可）**: 月次課金の満了を実時間で待つ必要はなく、
      解約直後に `/license/verify` がまだ `valid: true` を返すこと（内部条件:
      `cancel_at_period_end=true` かつ `periodEnd` が未来）をもって合格としてよい。
      確認方法: サイドバーで「Pro有効」のままであること、または
      `curl -X POST <BACKEND_URL>/license/verify -H 'content-type: application/json' -d '{"licenseKey":"<キー>"}'`
      の応答が `{"valid":true,"plan":"pro","periodEnd":<未来のUnix秒>}` であること
      （検証キャッシュ5分があるため、解錠直後に確認する場合は数分おく）
- [ ] 8. （任意・完全確認）Stripeダッシュボードのテストクロックで期間末を経過させ、
      verifyが `valid: false` に変わり、サイドバーがFree（月3枚）へ戻ることを確認
- [ ] 9. webhookイベント `checkout.session.completed` がStripeダッシュボード上で 200 応答になっている
